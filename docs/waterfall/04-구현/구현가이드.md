## 1. 문서 개요

### 1.1 목적

개발자가 수정 위치와 회귀 확인 절차를 찾도록 한다.

### 1.2 적용 범위와 독자

프런트엔드, Tauri/Rust, Bun API와 빌드·테스트 스크립트를 대상으로 한다. 제품 기획·개발·QA·릴리스 검토자가 사용한다.

### 1.3 기준과 판정

이 문서는 2026-09-25의 소스와 기록을 바탕으로 한 **검토 초안**이다. 문서화·코드 구현·실행 검증·일반 배포 승인은 서로 다른 상태다.

---

## 2. 개발 환경 설정

Apple Silicon macOS 14.2 이상 빌드 호스트에서 Xcode Command Line Tools, stable Rust/Cargo, Node.js 18+, pnpm, Bun, Python 3, CMake를 준비한다. 최종 사용자의 앱 설치 요구사항과 다르다. 정확한 설치·`llama-helper` 빌드·DMG 생성 명령은 [저장소 README](../../../README.md#build-a-development-dmg-from-source)를 따른다.

---

## 3. 코딩 규칙

기존 Next.js/React, Rust/Tauri, Bun 로컬 서버의 패턴과 타입 계약을 유지한다. 입력 검증은 [Zod 계약](../../../v2.0/meetily/frontend/src/local/contracts.ts)과 서버 경계에 둔다. 새 의존성이나 추상화보다 기존 청크·추론·DB 경로의 작은 변경을 우선한다. 오디오 실패를 빈 성공 응답으로 바꾸지 않는다.

---

## 4. 프로젝트 구조

| 범위 | 위치 |

| 모드·통역·회의 UI | `v2.0/meetily/frontend/src/local/` |
| 네이티브 앱·오디오·서비스 기동 | `v2.0/meetily/frontend/src-tauri/src/` |

빌드 호스트 준비물과 정확한 DMG 빌드 명령은 [저장소 README](../../../README.md#build-a-development-dmg-from-source)를 따른다. 개발 환경과 최종 사용자 설치 환경의 의존성을 혼동하지 않는다. 로컬 UI는 앱·서비스가 기동한 뒤 같은 Mac의 `http://127.0.0.1:3118/`에서 확인한다.

---

## 5. Git 변경 흐름

변경 목적에 해당하는 파일과 테스트만 커밋한다. 모델·개인 오디오·DB·DMG·비밀값·개인 절대 경로는 Git에서 제외한다. 원격 최신 상태를 확인하고 일반 push를 사용하며, 공개 `main`을 강제 재작성하지 않는다. 릴리스 산출물은 GitHub Release와 문서·checksum로 따로 식별한다.

## 7. 코드 리뷰와 검증

1. 변경할 [요구사항 ID](../01-요구사항분석/요구사항명세서-SRS.md)를 확인하고 계약·네이티브·브라우저 경계 중 영향을 받는 곳을 표시한다.
2. 오디오/DB 변경 시 실제 실패 또는 재현 가능한 fixture를 먼저 확보한다. 테스트가 개인 회의 음원을 Git에 넣지 않게 한다.
3. 가장 작은 소스 변경을 한 뒤 관련 로컬 테스트, TypeScript 검사, 필요하면 Rust 검사와 빌드를 수행한다. 명령은 [README의 검증 절](../../../README.md#validate-a-local-build)을 따른다.
4. 변경한 사용 흐름을 실제 앱과 localhost에서 실행하고, 네이티브/브라우저 증거를 구분한다. 실패를 숨기거나 부분 통과를 전체 통과로 적지 않는다.
5. [RTM](../01-요구사항분석/요구사항추적매트릭스-RTM.md), [테스트 결과](../05-테스트/테스트결과보고서.md), 릴리스 노트를 갱신한다.

개인 오디오·DB·모델·비밀값·DMG는 소스 커밋에 넣지 않는다. 빌드 산출물은 릴리스 절차에서 별도로 취급한다.

관련 로컬 테스트와 타입/Rust 검사 뒤 실제 macOS 앱·localhost의 바뀐 사용 흐름을 실행한다. 결과 보고 시 후보 버전·기기·미검증 경계를 명시한다.

## 8. 디버깅과 로깅

재현에는 입력원, 권한, 모델 준비, 회의 ID/청크 sequence, 발생 시각을 기록한다. 로그를 공유할 때 음성·전사·요약·토큰·사용자 경로를 제거한다. DB/오디오 원본은 보존하고 사본에서 검사한다. [장애 런북](../09-운영런북/장애대응-런북.md)을 따른다.

---

## 9. 성능과 보안 확인

지연은 발화 종료→전사와 전사→번역으로 나누고 30~60분 RSS·큐·누락을 측정한다. 서버의 loopback 바인딩·Host/Origin·client 헤더 검사, 업로드 크기와 정적 경로 검사를 회귀 항목으로 유지한다. 현재 장시간 목표 달성 증거는 없다.
