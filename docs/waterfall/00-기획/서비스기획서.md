## 1. 문서 개요

### 1.1 목적

Meetily2의 사용자 문제, 제품 목표와 작업 범위를 정의한다.

### 1.2 적용 범위와 독자

Apple Silicon macOS 앱과 같은 Mac의 localhost UI, 실시간 통역과 회의 기록을 다룬다. 제품 기획·개발·QA·릴리스 검토자가 사용한다.

### 1.3 기준과 판정

이 문서는 2026-09-25의 소스와 기록을 바탕으로 한 **검토 초안**이다. 문서화·코드 구현·실행 검증·일반 배포 승인은 서로 다른 상태다.

**제품:** Meetily2 · **범위:** Apple Silicon macOS 앱과 같은 Mac의 localhost UI · **기준:** 2026-09-25

## 2. 서비스 구조

1. 첫 실행에서 로컬 Whisper와 Ollama 모델을 준비하고 필요한 macOS 권한을 확인한다.
2. 시작 화면에서 **실시간 통역** 또는 **회의 녹음**을 고른다. 모드 선택만으로 음성 수집은 시작하지 않는다.
3. 실시간 통역에서는 입력원(컴퓨터 소리·마이크·둘 다)을 고르고 시작한다. 왼쪽 일본어, 오른쪽 한국어, 이전 발화 timeline을 확인한다. 이 경로는 회의 파일 생성이 목적이 아니다.
4. 녹음·가져오기에서는 전사 내용을 검토한 뒤 한국어 요약을 생성한다. 음성·전사·요약은 사용자의 로컬 환경에서 다룬다.
5. 앱이 실행 중이면 같은 Mac의 `http://127.0.0.1:3118/`에서 localhost UI를 사용할 수 있다. 브라우저 캡처는 별도 경로이므로 네이티브 캡처 성공을 그대로 적용하지 않는다.

네이티브 앱은 Core Audio의 컴퓨터 소리·마이크 경로를 다루고, localhost 브라우저는 브라우저 자체 캡처 권한을 쓴다. 두 화면이 같은 로컬 모델·저장 서비스를 이용하더라도 입력 캡처의 성공 여부는 따로 검증한다.

---

## 3. 핵심 메커니즘

입력 PCM을 짧은 발화 청크로 나눈 뒤 일본어 Whisper 전사와 Qwen3.5 4B의 한국어 번역을 순서대로 연결한다. 완료된 최근 두 턴은 다음 번역의 용어·어조 문맥으로 사용한다. 사용자는 좌우 자막과 이전 발화 timeline을 확인한다. 회의 모드는 전사와 오디오를 로컬 저장하고 별도로 요약한다. [아키텍처](../02-시스템설계/시스템아키텍처설계서-SAD.md)와 [상세 설계](../03-상세설계/상세설계서.md)에 처리 경계를 정의한다.

---

## 4. 핵심 기능과 사용자 가치

일본어로 진행되는 회의에서 사용자가 컴퓨터 소리와 마이크를 들으며 내용을 놓치지 않도록 일본어 인식 결과와 한국어 통역을 대화 순서대로 제공한다. 회의 후에는 별도 녹음·가져오기 흐름에서 전사와 한국어 회의록을 검토한다. 핵심 사용자는 일본어 회의 참여자와 한국어로 기록을 확인하는 사용자다.

가장 중요한 제품 가치는 음성을 **녹음 후 번역**하는 대신 진행 중 전사·통역을 보여 주고, 이전 대화를 잃지 않게 하는 것이다. 사용자는 중요한 표현을 원음과 다시 대조할 수 있어야 한다.

---

## 5. 배포와 유통 범위

현재 제품의 유통 단위는 Apple Silicon macOS DMG와 앱이 켜진 같은 Mac의 localhost 화면이다. RC6는 개발 후보이며 일반 배포가 아니다. 검색엔진 최적화·요금제·결제는 이 로컬 제품의 현재 구현 범위에 없고 사업 정책도 확정되지 않았다.

---

## 6. MVP 범위와 비목표

성공 기준은 통역의 **발화 순서 유지·이전 대화 보존**, 양쪽 입력원의 실제 동작, 측정된 지연·정확도·메모리, 전사/회의록 E2E, 안전한 Mac 설치다. 수치 목표와 합격 기준은 [테스트 계획](../05-테스트/테스트계획서.md)에서 기준선 측정 후 정한다. 현재 측정되지 않은 수치를 성능 보장으로 표기하지 않는다.

이 단계의 범위에는 Windows/Intel 배포, 서버 기반 공동 작업, 실시간 음성 합성 통역, 무검토 자동 회의록 확정이 없다. 모델 출력은 초안이며 중요한 내용은 사용자가 확인한다.

MVP의 검증 대상은 [SRS](../01-요구사항분석/요구사항명세서-SRS.md)의 FR-01~FR-09이다.

---

## 7. 성공 지표와 가설 검증

지연은 발화 종료→원문 표시와 원문 표시→번역 표시를 분리해 p50/p95로 측정한다. 품질은 입력원별 전사 누락·오인식, 고유명사·숫자·부정·어조 오류, 무음 환각으로 평가한다. 안정성은 30~60분 누적 메모리·큐·timeline 유지로 확인한다. 수치 합격선은 실측과 제품 판단 후 확정한다. 현재는 목표 달성 기록이 없다.

---

## 8. 현재 상태와 다음 단계

RC6는 개발용 미리보기다. 빌드 Mac의 통역 timeline과 UI 일부는 확인됐으나 혼합 오디오 정확도, 긴 세션 메모리, 브라우저 마이크, 새 후보의 회의록 E2E, 서명·공증·다른 Mac 설치가 남아 있다. [상태 기록](../../../reviews/STATE.md)을 배포 판정의 기준으로 삼는다.

다음 단계는 혼합 오디오 정확도와 장시간 자원 사용을 측정하고, 회의록 E2E와 깨끗한 다른 Mac에서의 설치·권한·공증을 검증하는 것이다.
