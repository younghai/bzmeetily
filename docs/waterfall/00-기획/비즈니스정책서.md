## 1. 문서 개요

### 1.1 목적

Meetily2의 화면 문구, 구현, QA가 동일한 사용자 동작 규칙을 따르도록 한다. 각 정책은 구체적인 조건과 결과를 가진다. 정책이 소스에 구현되어 있어도 실제 장비에서 검증되지 않았다면 완료로 표기하지 않는다.

### 1.2 범위와 대상 독자

Apple Silicon macOS 앱의 일본어→한국어 실시간 통역, 회의 녹음·가져오기·요약, 같은 Mac의 localhost UI, 개발 후보 배포를 다룬다. 제품 기획·개발·QA·릴리스 검토자가 사용한다. CRM의 인증·과금·영업 정책은 Meetily2의 현재 제품 범위가 아니므로 이 문서로 옮기지 않는다.

### 1.3 규칙의 상태와 관련 문서

`구현`은 현재 소스의 동작 경로, `부분 검증`은 특정 후보·기기·시나리오의 실행 기록, `미검증`은 출고 판단에 필요한 증거가 없음을 뜻한다. 요구사항은 [SRS](../01-요구사항분석/요구사항명세서-SRS.md), 사용자 흐름은 [유스케이스](../01-요구사항분석/유스케이스명세서.md), 후보 증거는 [테스트 결과](../05-테스트/테스트결과보고서.md)와 [릴리스 상태](../../../reviews/STATE.md)를 따른다. 보존 기간이나 일반 배포 승인을 임의로 확정하지 않는다.

## 2. 정책 목록 및 요약

| 정책 ID | 영역 | 핵심 규칙 | 현재 판정 |
|---------|------|-----------|-----------|
| BP-MODE | 시작 | 모드를 고른 뒤 별도 시작 동작에서 캡처한다 | 구현, 부분 검증 |
| BP-SOURCE | 입력원 | 마이크·컴퓨터 소리·혼합을 구분하고 요청한 입력의 실패를 알린다 | 구현, 혼합 정확도 미검증 |
| BP-LIVE | 통역 표시 | 일본어 왼쪽·한국어 오른쪽, 이전 발화 timeline 유지 | 구현, 짧은 실행 검증 |
| BP-DATA | 회의 데이터 | 실시간 자막은 자동 회의 저장이 아니며 회의 흐름은 로컬 저장한다 | 구현, 새 후보 E2E 미검증 |
| BP-AI | 모델 결과 | 전사·번역·요약은 검토할 초안이며 정확도 보장은 아니다 | 정책 적용 필요 |
| BP-LOCAL | 로컬 접근 | loopback 서비스와 macOS/브라우저 권한 경계를 유지한다 | 소스 확인, 운영 재검증 필요 |
| BP-ERROR | 실패 처리 | 모델·DB·입력·빈 전사 오류를 성공처럼 표시하지 않는다 | 일부 구현, 실제 복구 검증 필요 |
| BP-RELEASE | 배포 | ad-hoc RC는 개발 후보이며 일반 배포는 별도 게이트를 통과한다 | 일반 배포 미승인 |

## 3. 모드 선택과 음성 수집 정책

### 3.1 목적

사용자가 의도하지 않은 녹음 또는 통역을 시작하지 않도록 한다.

### 3.2 규칙

| 규칙 ID | 조건과 결과 | 근거 |
|---------|-------------|------|
| BP-MODE-001 | 시작 화면에서 통역/녹음 모드를 선택해도 캡처는 열리지 않는다. 별도의 **시작** 조작 후에만 입력을 처리한다. | [제품 사용 흐름](../../../README.md#install-and-run) |
| BP-MODE-002 | 실시간 통역과 회의 녹음은 다른 작업 흐름으로 표시한다. 실시간 통역을 회의 파일이 자동 생성된 것으로 설명하지 않는다. | [제품 기능](../../../README.md#what-it-does) |
| BP-SOURCE-001 | 네이티브 통역의 입력원은 마이크, 컴퓨터 소리, 두 입력의 혼합으로 구분한다. | [오디오 설계](../02-시스템설계/시스템아키텍처설계서-SAD.md) |
| BP-SOURCE-002 | 컴퓨터 소리를 요청했는데 시작할 수 없으면 오류를 표시한다. 마이크만 수집한 결과를 요청한 혼합 입력 성공으로 보고하지 않는다. | [RC6 노트](../../../v2.0/docs/release-2.0.2-rc.6.md) |

### 3.3 예시와 검증

| 상황 | 기대 결과 | 확인 케이스 |
|------|-----------|-------------|
| 통역 모드만 선택하고 기다림 | 입력 장치 사용 표시와 자막 생성이 시작되지 않음 | TC-01 |
| 컴퓨터 소리 권한 거부 후 혼합 입력 시작 | 명시적 실패 표시, 조용한 마이크 단독 전환 금지 | TC-02 |
| 브라우저에서 컴퓨터 소리 공유 불가 | 브라우저 기능 제한으로 안내하고 네이티브와 동일하다고 주장하지 않음 | TC-07 |

## 4. 실시간 통역과 timeline 정책

### 4.1 목적

현재 발화뿐 아니라 앞선 대화 흐름을 유지해 사용자가 일본어 원문과 한국어 해석을 다시 대조할 수 있게 한다.

### 4.2 규칙

| 규칙 ID | 조건과 결과 | 현재 판정 |
|---------|-------------|-----------|
| BP-LIVE-001 | 일본어 전사는 왼쪽, 대응하는 한국어 번역은 오른쪽에 표시한다. | 화면 구현 |
| BP-LIVE-002 | 새 발화가 들어와도 완료된 이전 발화 카드를 timeline에 남긴다. 첫/최근 발화로 이동할 수 있어야 한다. | RC4 짧은 실행 확인, 장시간 미검증 |
| BP-LIVE-003 | 일본어 전사가 수정되면 이전 한국어 결과를 지우고 해당 수정본의 번역만 다시 연결한다. | 소스·테스트 기록 |
| BP-LIVE-004 | 번역 문맥에는 완료된 일본어/한국어 발화 중 최근 최대 2턴만 사용한다. 미완료 결과를 확정 문맥으로 사용하지 않는다. | 소스 구현 |

### 4.3 예시와 검증

첫 번째 발화가 번역된 뒤 두 번째 발화의 번역이 지연되면, 첫 번째 카드는 그대로 남고 두 번째 카드는 진행 상태를 보인다. 두 번째 일본어 문장이 수정되면 낡은 한국어 번역을 해당 카드에 계속 붙여 두지 않는다. [TC-03](../05-테스트/테스트케이스.md)과 [TC-04](../05-테스트/테스트케이스.md)로 확인한다. 30~60분 이력 안정성은 아직 합격하지 않았다.

## 5. 회의 데이터 정책

### 5.1 목적

일시적인 통역 자막과 사용자가 보관할 회의 기록을 구분한다.

### 5.2 규칙

| 규칙 ID | 조건과 결과 | 비고 |
|---------|-------------|------|
| BP-DATA-001 | 실시간 통역 자막은 회의 DB에 자동 저장된 것으로 간주하지 않는다. 필요한 경우 복사·텍스트 내보내기를 사용한다. | 녹음 흐름과 분리 |
| BP-DATA-002 | 회의 녹음·파일 가져오기 흐름은 로컬 회의 DB, 전사·요약 메타데이터와 로컬 오디오 파일을 사용한다. | [DB 설계](../02-시스템설계/데이터베이스설계서.md) |
| BP-DATA-003 | 같은 회의의 같은 청크 순번이 재전송되면 중복 전사를 만들지 않고 저장된 receipt를 돌려준다. | [API 설계](../02-시스템설계/API설계서.md) |
| BP-DATA-004 | 개인 오디오·회의 DB·모델·비밀값을 공개 소스 저장소에 추가하지 않는다. | [소스 안내](../../../README.md) |

### 5.3 예시와 미결정 사항

통역 화면만 사용하고 종료한 사용자는 나중에 회의 목록에서 그 세션을 자동으로 찾을 수 있다고 기대해서는 안 된다. 반면 파일 가져오기로 만든 회의는 전사와 오디오를 로컬에서 다시 조회할 수 있어야 한다. 사용자 데이터의 보존 기간, 완전 삭제 UI, 자동 백업 정책은 아직 승인되지 않았다. [TC-05~TC-06](../05-테스트/테스트케이스.md)에서 저장·재조회를 검증한다.

## 6. AI 결과 검토 정책

### 6.1 목적

모델 출력을 사실 또는 확정 회의록으로 오인하지 않도록 한다.

### 6.2 규칙

| 규칙 ID | 조건과 결과 |
|---------|-------------|
| BP-AI-001 | ASR 전사, 한국어 통역, 요약은 검토할 초안으로 표시한다. |
| BP-AI-002 | 이름, 숫자, 부정 표현, 결정 사항은 중요한 사용 전에 원음 또는 참석자 기록과 대조한다. |
| BP-AI-003 | 문맥 2턴은 용어·존댓말 유지에 도움을 주는 설계지만 정확도 보장 문구로 사용하지 않는다. |
| BP-AI-004 | 무음 구간에서 생성된 발화는 실제 음성이 확인되기 전 사실로 채택하지 않는다. |

### 6.3 예시와 증거

RC4의 짧은 혼합 입력 시험에서는 이전 카드 4개가 남았지만 조용한 구간에서 ASR 환각도 관찰되었다. 따라서 timeline 동작 확인과 번역 정확도 승인은 별도다. 고유명사·숫자·존댓말 샘플의 원음 대조와 지연 측정은 [테스트 계획](../05-테스트/테스트계획서.md)에 따라 수행한다.

## 7. 로컬 접근 및 권한 정책

### 7.1 목적

앱/브라우저 캡처와 로컬 API의 접근 경계를 사용자에게 분명히 설명한다.

### 7.2 규칙

| 규칙 ID | 조건과 결과 |
|---------|-------------|
| BP-LOCAL-001 | 로컬 서버는 `127.0.0.1`에 바인딩한다. 같은 Mac의 `localhost:3118` UI로 접근한다. |
| BP-LOCAL-002 | 로컬 API의 Host·Origin을 검사하고 변경 요청에 `X-Meetily-Client` 헤더를 요구한다. |
| BP-LOCAL-003 | 네이티브 마이크/컴퓨터 소리 권한과 브라우저 마이크/화면 공유 권한은 별도로 안내·검증한다. |
| BP-LOCAL-004 | 첫 모델 다운로드에는 네트워크가 필요할 수 있으며, 설치 후 추론은 로컬 서비스 경로로 처리한다. |

### 7.3 예시와 검증

다른 컴퓨터에서 `3118` 포트 접속이 성공한다면 loopback 경계 위반이다. 같은 Mac의 브라우저에서 권한을 거부했다면 네이티브 앱의 권한 승인 여부만으로 브라우저 캡처 성공을 판단하지 않는다. [TC-07~TC-08](../05-테스트/테스트케이스.md)에서 구분한다.

## 8. 오프라인 및 오류 처리 정책

### 8.1 목적

음성·모델·DB 실패를 빈 전사나 정상 종료로 숨기지 않도록 한다.

### 8.2 규칙

| 규칙 ID | 조건과 결과 |
|---------|-------------|
| BP-ERROR-001 | 모델 준비 실패·타임아웃·포트 충돌은 상태 또는 오류로 표시하고 재시도 경로를 제공한다. |
| BP-ERROR-002 | 회의 DB가 아직 준비되지 않았으면 로컬 API가 503을 돌릴 수 있다. 이를 '회의 없음'으로 바꾸지 않는다. |
| BP-ERROR-003 | 요약 요청에 전사가 비어 있으면 409 오류를 돌리고 빈 회의록을 성공으로 저장하지 않는다. |
| BP-ERROR-004 | 컴퓨터 소리 캡처 실패는 요청한 입력 실패로 보여 준다. |

### 8.3 예시와 복구

모델이 시작되지 않아 전사가 한 건도 생성되지 않으면 사용자는 통역 성공 화면 대신 모델 상태와 실패 원인을 본다. 기존 회의 DB를 지우지 않고 서비스 상태·권한·포트를 순서대로 확인한다. 운영 절차는 [장애 런북](../09-운영런북/장애대응-런북.md)을 따른다.

## 9. 배포 승인 정책

### 9.1 목적

빌드 성공과 일반 사용자에게 배포할 준비가 된 상태를 구분한다.

### 9.2 규칙

| 규칙 ID | 조건과 결과 |
|---------|-------------|
| BP-RELEASE-001 | RC6의 ad-hoc 서명 DMG는 신뢰된 테스트 Mac용 개발 후보로만 표기한다. |
| BP-RELEASE-002 | 일반 배포는 Developer ID 서명·공증, 다른 깨끗한 Mac 설치·권한·첫 모델 다운로드 검증이 필요하다. |
| BP-RELEASE-003 | 혼합 오디오 정확도, 조용한 구간 환각, 30~60분 메모리, 새 후보의 회의록 E2E가 미검증이면 일반 배포를 승인하지 않는다. |
| BP-RELEASE-004 | 기존 DMG를 덮어쓰지 않고 버전·checksum·릴리스 노트로 후보를 식별한다. |

### 9.3 예시와 현재 상태

RC6에서 창 컨트롤과 DMG 이미지 검사가 통과했더라도, RC6 음성 정확도와 clean-Mac 게이트가 열려 있으므로 '정식 배포 완료'로 표시하지 않는다. 구체적인 순서는 [배포 계획](../06-배포/배포계획서.md)에 있다.

## 10. 정책 변경 관리

정책을 변경할 때는 해당 BP ID를 유지하거나 새 ID를 부여하고, [SRS](../01-요구사항분석/요구사항명세서-SRS.md) → [RTM](../01-요구사항분석/요구사항추적매트릭스-RTM.md) → 설계·코드 → [테스트 케이스](../05-테스트/테스트케이스.md) → 실행 결과 순으로 갱신한다. 문서의 승인자는 아직 지정되지 않았으며, 이 초안의 변경이력은 사용자 승인 이력으로 해석하지 않는다.
