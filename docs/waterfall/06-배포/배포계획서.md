# macOS 배포 계획서

## 후보와 일반 배포의 구분

현재 확인된 [2.0.2 RC6](../../../v2.0/docs/release-2.0.2-rc.6.md)는 ad-hoc 서명된 Apple Silicon 개발 후보이며 일반 승인 릴리스가 아니다. 배포 게이트의 기준은 [3회 점검 상태](../../../reviews/STATE.md)와 [clean-Mac 체크리스트](../../../v2.0/docs/clean-mac-checklist.md)다.

## 작업 순서

1. 변경 범위·요구사항 ID·테스트 결과·알려진 문제를 고정하고 릴리스 노트를 작성한다. 개인 오디오·DB·모델·비밀값·로컬 사용자 경로가 패키지/소스에 들어가지 않았는지 검사한다.
2. [빌드 가이드](../../../README.md#build-a-development-dmg-from-source)에 따라 Apple Silicon 빌드 호스트에서 새 버전으로 `v2.0/scripts/build-dmg.sh`를 실행한다. 기존 DMG 파일을 덮어쓰지 않는다.
3. 개발 후보는 checksum·DMG 이미지·ad-hoc 서명 검증 후 명시적으로 prerelease로 표시한다. 일반 배포 후보는 별도의 `--dist` Developer ID 서명·공증 경로를 사용한다. 자격 증명 없이는 이 단계를 완료로 표시하지 않는다.
4. 실제 빌드 Mac에서 통역 세 입력원, timeline, 회의 녹음/가져오기/요약, localhost를 실행한다. 조용한 구간·실패·재시작을 포함한다.
5. 별도의 깨끗한 Mac에서 DMG 마운트→Applications 설치→첫 실행→모델 다운로드→권한 승인/거부→마이크/컴퓨터 소리→회의록을 테스트한다. 30~60분 메모리와 혼합 오디오 정확도 결과를 수집한다.
6. 릴리스 게이트 기록에 통과 증거·미해결 결함·출고 결정을 남긴 뒤에만 일반 배포 상태로 게시한다.

## 롤백과 현재 차단 사유

기존 설치·사용자 데이터를 삭제해 롤백하지 않는다. 후보에서 심각한 문제가 나면 해당 릴리스만 더 이상 권장하지 않고, 이전에 검증된 앱을 재설치할 수 있도록 안내한다. DB 스키마가 바뀐 경우에는 원본 데이터를 보존한 사본으로 이전/되돌림을 검증해야 한다.

현재 일반 배포 차단: 혼합 오디오 정확도와 무음 환각, 장시간 메모리, 브라우저 마이크 E2E, 회의록의 새 후보 E2E, 첫 설치·권한, Developer ID 서명/공증, 두 번째 Mac 검사. 일정 경과만으로 해제하지 않는다.
