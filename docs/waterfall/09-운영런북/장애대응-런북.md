## 1. 문서 개요

### 1.1 목적

현장에서 관찰한 증상에서 원인 확인과 안전한 복구로 이어지는 절차를 제공한다.

### 1.2 적용 범위와 독자

앱·모델·오디오·timeline·회의 데이터·DMG 문제를 다룬다. 제품 기획·개발·QA·릴리스 검토자가 사용한다.

### 1.3 기준과 판정

이 문서는 2026-09-25의 소스와 기록을 바탕으로 한 **검토 초안**이다. 문서화·코드 구현·실행 검증·일반 배포 승인은 서로 다른 상태다.

먼저 세션의 중요도를 확인한다. 중요한 회의 중에는 Meetily2만을 유일한 기록 수단으로 의존하지 말고 가능한 별도 원본 기록을 확보한다. 진단 과정에서 DB·오디오·모델을 삭제하거나 초기화하지 않는다.

---

## 2. 목적과 범위

중요한 회의에서는 Meetily2만을 유일한 기록으로 삼지 않고 가능한 원본 오디오를 확보한다. DB·오디오·모델을 진단 목적만으로 삭제하지 않는다.

---

## 3. 장애 등급

| 등급 | 기준 | 예 |
|------|------|----|
| 차단 | 회의 데이터 손실 또는 입력 음성 누락 | 혼합 입력 0청크, DB 손상 |
| 높음 | 통역 정확도·지연 때문에 사용 불가 | 무음 환각, 연속 번역 실패 |
| 보통 | 우회 가능하지만 UX 저하 | timeline 탐색·창 크기 문제 |

등급별 SLA는 아직 승인되지 않았다.

---

## 4. 공통 대응 절차

1. 후보·macOS·입력원·모델·권한과 사건 시각을 기록한다.
2. 앱/서비스 상태와 포트를 확인하고 사용자 오디오·DB 원본을 보존한다.
3. 마이크/컴퓨터 소리/혼합 또는 브라우저 경로를 분리해 재현한다.
4. 로그·화면·측정값의 개인정보를 제거한다.
5. 수정 후 동일 조건 E2E와 관련 회귀를 다시 실행한다.

## 5. 시나리오별 즉시 조치

| 증상 | 우선 확인 | 복구·증거 |
| --- | --- | --- |
| 앱/localhost가 열리지 않음 | 앱 실행 여부, 3118 포트 충돌, `GET /api/local/status` | 중복 앱/서비스를 식별해 종료 후 재기동; 상태·시각 기록 |
| 모델 준비 실패 | status의 Whisper/Ollama 오류, 8178/11434 포트, 모델 설치 상태 | 모델 설정·로그 확인 후 재시도; 기존 DB 유지 |
| 음성 청크 0개 | 시작 버튼·입력원·마이크/컴퓨터 소리 권한·실제 입력 신호 | 입력원별 짧은 재현. 컴퓨터 소리 실패를 mic-only 성공으로 보고하지 않음 |
| 전사/번역 늦거나 끊김 | 모델 준비·추론 큐, CPU/RSS, 청크 순서, 세션 중 오류 | 발화 종료/표시 시각·누락 순번을 기록하고 짧은 재현으로 분리 |
| timeline 이전 내용 사라짐 | 카드 개수, 첫/최근 탐색, 원문 수정 시 번역 상태 | 같은 발화 시퀀스와 화면 증거로 회귀 재현 |
| 회의/요약이 보이지 않음 | 회의 ID·전사 존재·DB 준비(503)·빈 전사(409) | 원본 DB/sidecar/오디오 백업 후 사본에서 조회 |
| DMG 설치 경고/실패 | 후보 버전·checksum·서명·공증·OS/CPU | ad-hoc RC6와 일반 배포 차이를 명시, clean-Mac 항목 기록 |

## 6. 복구 확인 체크리스트

| 확인 | 통과 기준 |
|------|-----------|
| 서비스 | `/api/local/status`에서 필요한 모델 준비 확인 |
| 입력 | 선택한 음성원이 실제 청크를 만듦 |

| 데이터 | 백업 사본과 원본의 회의 수·내용 비교 |
