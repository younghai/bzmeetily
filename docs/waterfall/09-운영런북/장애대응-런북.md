# 장애 대응 런북

먼저 세션의 중요도를 확인한다. 중요한 회의 중에는 Meetily2만을 유일한 기록 수단으로 의존하지 말고 가능한 별도 원본 기록을 확보한다. 진단 과정에서 DB·오디오·모델을 삭제하거나 초기화하지 않는다.

| 증상 | 우선 확인 | 복구·증거 |
| --- | --- | --- |
| 앱/localhost가 열리지 않음 | 앱 실행 여부, 3118 포트 충돌, `GET /api/local/status` | 중복 앱/서비스를 식별해 종료 후 재기동; 상태·시각 기록 |
| 모델 준비 실패 | status의 Whisper/Ollama 오류, 8178/11434 포트, 모델 설치 상태 | 모델 설정·로그 확인 후 재시도; 기존 DB 유지 |
| 음성 청크 0개 | 시작 버튼·입력원·마이크/컴퓨터 소리 권한·실제 입력 신호 | 입력원별 짧은 재현. 컴퓨터 소리 실패를 mic-only 성공으로 보고하지 않음 |
| 전사/번역 늦거나 끊김 | 모델 준비·추론 큐, CPU/RSS, 청크 순서, 세션 중 오류 | 발화 종료/표시 시각·누락 순번을 기록하고 짧은 재현으로 분리 |
| timeline 이전 내용 사라짐 | 카드 개수, 첫/최근 탐색, 원문 수정 시 번역 상태 | 같은 발화 시퀀스와 화면 증거로 회귀 재현 |
| 회의/요약이 보이지 않음 | 회의 ID·전사 존재·DB 준비(503)·빈 전사(409) | 원본 DB/sidecar/오디오 백업 후 사본에서 조회 |
| DMG 설치 경고/실패 | 후보 버전·checksum·서명·공증·OS/CPU | ad-hoc RC6와 일반 배포 차이를 명시, clean-Mac 항목 기록 |

공유 가능한 이슈에는 후보 버전, macOS/CPU, 재현 단계, 입력원, 모델 버전, 예상/실제, 로그의 **개인정보 제거본**만 남긴다. [운영 가이드](../06-배포/운영가이드.md)와 [배포 게이트](../06-배포/배포계획서.md)를 연결해 재발 방지 여부를 판단한다.
