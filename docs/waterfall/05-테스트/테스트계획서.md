## 1. 문서 개요

### 1.1 목적

요구사항의 수용 여부를 판단할 환경, 검증 층과 증거 기준을 정한다.

### 1.2 적용 범위와 독자

소스·서비스·네이티브·브라우저·장시간·배포 시험을 포함한다. 제품 기획·개발·QA·릴리스 검토자가 사용한다.

### 1.3 기준과 판정

이 문서는 2026-09-25의 소스와 기록을 바탕으로 한 **검토 초안**이다. 문서화·코드 구현·실행 검증·일반 배포 승인은 서로 다른 상태다.

---

## 2. 테스트 전략

요구사항 ID를 [RTM](../01-요구사항분석/요구사항추적매트릭스-RTM.md)으로 TC와 연결한다. 소스 검사는 빠른 회귀, 로컬 API 스모크는 서비스 계약, 실제 앱/브라우저는 권한·오디오 경로, clean-Mac은 배포 게이트를 확인한다. 한 층의 통과를 다른 층의 통과로 대체하지 않는다.

---

## 3. 테스트 범위

| 층 | 수행과 기록 |
| --- | --- |
| 소스 | 로컬 테스트, TypeScript, Rust, Next/Tauri 빌드; 실행 건수·건너뜀·실패 분리 |
| 로컬 서비스 | status·전사·번역·요약·loopback·오류 응답, 요청 크기·origin 검사 |
| 네이티브 E2E | 세 입력원, 권한 승인/거부, 연속 발화·timeline, 녹음·회의록, 창 조작 |
| 브라우저 E2E | 실제 브라우저 권한으로 마이크·가능한 컴퓨터 소리 공유·좌우 자막·저장 흐름 |
| 장시간/정확도 | 30~60분 RSS·메모리 압력·큐·자막 지연, 원음 대비 ASR/번역 오류 표본 |
| 릴리스 | checksum·DMG 마운트·서명·공증·다른 Mac 첫 실행·모델 다운로드 |

지연은 `발화 종료→전사 표시`, `전사 표시→번역 표시`를 분리해 p50/p95와 누락률을 기록한다. 정확도는 정답 전사와 핵심 의미·이름·숫자·부정·존댓말/어조를 샘플별로 평가한다. 합격 수치의 임의 소급 설정은 금지한다. 측정 후 제품 수용 기준을 명시하고 재검증한다. 혼합 오디오에서는 컴퓨터 소리와 마이크를 각각 확인하고, 조용한 구간의 환각을 별도 계수한다.

실행 템플릿은 [테스트 케이스](테스트케이스.md), 현 시점 증거는 [결과 보고서](테스트결과보고서.md)와 [기존 3회 기록](../../../reviews/STATE.md)에 있다. 단위 테스트 통과는 하드웨어·배포 검증을 대신하지 않는다.

모드 선택·세 입력원·JA→KO 자막·timeline·회의 녹음/가져오기/요약·localhost·오류·설치를 포함한다. Windows/Intel·원격 공동 작업·음성 합성은 현재 범위 밖이다.

---

## 4. 테스트 환경

일본어→한국어 실시간 통역, 컴퓨터 소리·마이크·혼합, 이력 보존, 회의 녹음/가져오기/요약, localhost와 macOS 패키지의 차이를 확인한다. 기본 환경은 Apple Silicon macOS 빌드 Mac, 모델 설치, 로컬 Whisper/Ollama다. 일반 배포 판정에는 별도의 깨끗한 Mac이 필요하다. 개인 오디오 대신 공개·합성 또는 동의가 확보된 평가 음원을 사용한다.

후보 버전, macOS/CPU, 오디오 장치와 권한, Whisper/Ollama 모델 버전, 브라우저 종류를 결과마다 기록한다. 개인 회의 음원을 공개 저장소에 보관하지 않는다.

## 5. 진입과 종료 기준

| 단계 | 진입 조건 | 종료 조건 |
|------|-----------|-----------|
| 소스 회귀 | 변경 코드·fixture 준비 | 관련 테스트·타입 검사 통과 또는 실패 원인 기록 |
| 실제 통역 | 모델·권한·입력 장치 준비 | 원문/번역·timeline·오류·지연 증거 확보 |
| 일반 배포 | 서명·공증 후보, 별도 Mac | [clean-Mac 항목](../../../v2.0/docs/clean-mac-checklist.md)과 P0 차단 항목 충족 |

## 6. 일정과 리소스

검증 순서는 소스→로컬 서비스→네이티브·브라우저→장시간/정확도→clean-Mac이다. 별도의 검증 Mac, 세 입력원을 재현할 오디오, 설치 계정과 서명 자격 증명이 필요하다. 승인된 일정·담당자는 아직 없으므로 날짜를 확정하지 않는다.

---

## 7. 위험 관리

혼합 오디오 0청크·오인식, 무음 환각, 모델 지연/포트 충돌, 긴 세션 메모리, 브라우저 공유 제한, 첫 실행 권한/서명이 주요 위험이다. 실패 시 원음·로그·화면 증거를 보존하되 개인정보를 제거하고 해당 후보의 릴리스 게이트를 차단한다.

---

## 8. 보고 체계

각 TC의 기대/실제, 통과/실패/미실행, 환경, 실행일, 증거 위치를 [결과 보고서](테스트결과보고서.md)에 기록한다. 재현 불가나 미실행을 통과로 표시하지 않는다. 성능은 p50/p95, 누락률, 시간별 RSS를 원시 관측값과 함께 남긴다.

---

## 9. UX와 접근성 계획

좌우 문장 줄바꿈, 긴 대화 이력, 첫/최근 이동, 좁은 창, macOS 창 컨트롤, 키보드 초점·오류 텍스트를 실제 앱과 localhost에서 확인한다. 네이티브와 브라우저의 증거를 각각 남긴다.
