## 1. 문서 개요

### 1.1 목적

로컬 API 변경이 소스·계약·테스트·문서에 함께 반영되도록 한다.

### 1.2 적용 범위와 독자

Bun /api/local 경로, Zod 계약, localhost 보안·오류 규칙을 다룬다. 제품 기획·개발·QA·릴리스 검토자가 사용한다.

### 1.3 기준과 판정

이 문서는 2026-09-25의 소스와 기록을 바탕으로 한 **검토 초안**이다. 문서화·코드 구현·실행 검증·일반 배포 승인은 서로 다른 상태다.

---

## 2. 계약 단일 소스

실제 라우트는 [app.ts](../../../v2.0/meetily/frontend/local-server/app.ts), 요청·응답 형식은 [contracts.ts](../../../v2.0/meetily/frontend/src/local/contracts.ts) 및 로컬 테스트가 기준이다. [API 설계서](../02-시스템설계/API설계서.md)는 이를 설명하는 문서이며 별도의 배포 API 약속이 아니다.

새 필드·엔드포인트·오류 상태를 바꾸면 다음 순서로 갱신한다: 계약 스키마 → 서버/클라이언트 → 정상·오류 로컬 테스트 → 실제 localhost 요청 → API 설계·RTM·릴리스 기록. 회의 청크 sequence의 멱등성과 번역의 `ja→ko`, 최대 2턴 문맥 제약을 회귀 항목으로 유지한다. 실패 응답을 무조건 성공처럼 표시하지 않는다.

---

## 3. 변경 시 필수 절차

요구사항과 BP 정책 확인 → Zod 계약·서버·클라이언트 동시 변경 → 정상/오류 로컬 테스트 → 실제 localhost 요청 → API 설계·RTM·테스트 결과 갱신 순서로 진행한다. DB 필드가 바뀌면 원본이 아닌 사본 마이그레이션 시험을 먼저 수행한다.

---

## 4. API 보안 계약

- 서버의 `127.0.0.1` 바인딩과 origin/client 헤더 검사를 유지하고, 외부 네트워크 노출을 출시 전 재확인한다.
- 오디오 업로드 크기, 처리 시간, import 형식과 정적 파일 경로 검사를 유지한다. 원본 오디오·전사·요약을 CI 로그나 공개 샘플에 넣지 않는다.
- DB 준비 지연(503), 빈 전사(409), 권한·모델 실패를 구분해 UI/테스트에 드러낸다.
- 하드웨어 E2E와 장시간 정확도는 API 테스트만으로 대체하지 않는다.

API 계약과 릴리스 후보의 검증 결과가 다르면 실제 코드·테스트·후보 증거를 우선하고 문서를 수정한다. OpenAPI/Postman 파일은 이 저장소에 현재 별도 계약으로 제공되지 않으므로 존재한다고 표기하지 않는다.

변경 요청 헤더는 인증 토큰이 아니라 로컬 호출 방어 요소다. 이 정책으로 임의의 원격 클라이언트 접속을 승인하지 않는다.

---

## 5. 필수 검증 명령과 경로

소스 검사는 [README](../../../README.md#validate-a-local-build)의 `pnpm test:local`, `pnpm exec tsc --noEmit`, `pnpm build`, 필요한 Rust 테스트를 따른다. 로컬 서비스가 실행되면 `/api/local/status`, 정상 회의 요청, 권한/형식 오류를 실제로 확인한다. 오디오 경로의 네이티브 E2E는 별도다.

---

## 6. 변경 요청 체크리스트

| 확인 | 결과 기록 |
|------|-----------|
| 계약 필드·응답 상태 | 정상·오류 예시 |
| Host/Origin/헤더 | 거부·허용 케이스 |
| 청크 멱등성 | 동일 sequence 재요청 결과 |
| 개인 데이터 | 로그·fixture·커밋 유출 없음 |
| 문서와 RTM | 같은 후보 버전으로 갱신 |

---

## 7. 버전과 변경 정책

이 로컬 API에는 별도의 공개 버전·OpenAPI 산출물이 아직 없다. 계약을 변경할 때 호환성 영향을 앱과 localhost UI 양쪽에서 검사한다. 새 버전 번호나 외부 연동 안정성을 승인 없이 약속하지 않는다.

---

## 8. 릴리스 승인 기준

API 테스트만 통과해도 릴리스가 완료되는 것은 아니다. 실제 통역, 회의록, 장시간 안정성, 서명·공증·clean-Mac 항목의 게이트를 [배포 계획](../06-배포/배포계획서.md)과 함께 확인한다.
